# Deploying Origin

Three pieces: the **web app** (Next.js, `apps/web`) on Vercel, the **API** (FastAPI, `apps/api`) on Render's free plan (or any Docker host), and **Postgres** on Supabase's free plan. The browser only ever talks to the web origin; Next proxies `/api/v1/*` to the API, so no CORS or public API URL is needed in the browser.

## 1. Database on Supabase (free)

1. https://supabase.com → New project → pick a region close to your users → set a **database password** (keep it).
2. Project → **Connect** (top bar) → **Session pooler** → copy the URI. It looks like
   `postgresql://postgres.<ref>:[YOUR-PASSWORD]@aws-0-<region>.pooler.supabase.com:5432/postgres`.
   Replace `[YOUR-PASSWORD]` with the password from step 1. Use the *Session* pooler (port 5432), not the *Transaction* pooler (6543) — SQLAlchemy needs session semantics; the direct connection is IPv6-only, which Render cannot reach.

The API accepts `postgres://` / `postgresql://` URLs and adds the psycopg driver itself. Migrations run automatically on every start.

## 2. API on Render (free)

1. Render dashboard → **New → Blueprint** → select `sssss31/origin-design-agent-os`. Render reads `render.yaml` and creates `origin-api` (Docker, **Free** plan).
2. Fill in when asked:
   * `DATABASE_URL` = the Supabase URI from above
   * `BOOTSTRAP_ADMIN_PASSWORD` = a password of at least 16 characters (creates the first admin only; change it after the first login)
   `ALLOWED_ORIGINS` / `FRONTEND_URL` are pre-filled with the Vercel URL — edit them if your domain differs.
3. Deploy. The container runs `alembic upgrade head` first, then uvicorn. Health check: `https://<your-api>.onrender.com/healthz`.

`JWT_SECRET` and `ENCRYPTION_KEY` are generated by Render; the API derives a Fernet key from `ENCRYPTION_KEY`, so stored agent API keys stay readable across restarts. **Never change `ENCRYPTION_KEY` after agents are connected** — their keys would become unreadable.

Free-plan notes: the service sleeps after 15 minutes without traffic and the first request afterwards takes 30–60 s; uploaded files live on the instance disk and are lost on redeploy (set `STORAGE_BACKEND=s3` with `OBJECT_STORAGE_*` for durable uploads — Supabase Storage is S3-compatible). `SINGLE_INSTANCE=true` keeps one instance simple (inline job queue, in-memory events).

## 3. Web on Vercel

The repo is a monorepo, so Vercel must build `apps/web`, not the repo root (a root build produces nothing and every URL returns Vercel's `404 NOT_FOUND`).

1. Vercel → project **origin-design-agent-os** → **Settings → General → Root Directory** → `apps/web` → Save.
2. **Settings → Environment Variables** → add `API_PROXY_TARGET` = `https://<your-api>.onrender.com` (no trailing slash) for Production (and Preview if wanted).
3. **Deployments → ⋯ → Redeploy** (or push a commit).

Framework preset stays "Next.js"; the build command is the default `next build`. `output: "standalone"` is disabled automatically on Vercel.

## 4. First login

Open the Vercel URL → sign in with `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD` → account menu → **Admin console → Agents** → add your GPT agents' endpoints and API keys → Test.

## Self-hosting with Docker instead

`infra/docker-compose.yml` runs Postgres, the API (`infra/deploy/api.Dockerfile`) and the web (`infra/deploy/web.Dockerfile`). Set the same environment variables as above; `API_PROXY_TARGET` for the web container is the API container's URL.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Vercel shows `404 NOT_FOUND` on every page | Root Directory is the repo root | Set Root Directory to `apps/web`, redeploy |
| Login says "Request failed" / network error | `API_PROXY_TARGET` missing or wrong | Set it to the API origin, redeploy the web |
| Login works but chat replies fail with a CORS error | `ALLOWED_ORIGINS` does not include the web URL | Add the exact `https://…` origin, restart the API |
| "the stored credential cannot be read" | `ENCRYPTION_KEY` changed after keys were saved | Restore the old value, or re-enter the agent keys |
| API refuses to start with "Invalid production configuration" | A required variable is missing | The message lists what to set |
